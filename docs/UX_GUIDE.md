# UX 가이드

FinSight 화면이 **처음 온 사람을 붙잡고, 한 단계씩 다음 단계로 넘기도록** 만드는 규칙이다.
- 원칙 출처: Figma「UI 디자인 원칙」 7가지(계층 구조·점진적 공개·일관성·대비·접근성·근접성·정렬)와 실천 팁 4가지.
- 색·컴포넌트 클래스는 `docs/UI_GUIDE.md`, 화면 분기는 `docs/USER_FLOWS.md`, 지표 정의는 `docs/PRD.md`를 따른다. 이 문서는 그 위에서 **무엇을 먼저 보여 주고 무엇을 누르게 할지**를 정한다.
- "(있음)"은 이미 구현된 것, "→ Bn"은 §10 백로그 항목이다. **백로그는 그 항목을 맡은 step에서만 구현한다.** 다른 step에서 미리 고치지 않는다.

## 1. 한 줄 원칙
> 모든 화면은 사용자가 지금 서 있는 단계에서 **다음 단계로 가는 행동 하나**를 가장 또렷하게 보여 준다.

- 화면마다 답하는 질문 하나, 가장 큰 요소(주인공) 하나, 포인트 색 채움 버튼 하나.
- 막다른 화면이 없다. 빈 상태·에러·완료 화면에도 다음 행동이 있다.
- 가치 먼저, 요구는 나중. 가입 전에 결과(데모)를, 결제 전에 내 데이터의 일부(티저)를 보여 준다.

## 2. 단계 지도
```
S0 발견 → S1 맛보기 → S2 가입 → S3 파일 확보 → S4 첫 올리기 → S5 Aha → S6 채우기 → S7 전환
   /        /demo    /login·동의  /upload·/guide  /upload[/id]  /dashboard  시작 체크리스트  /pricing
                                                                   ▲
                                        S8 재방문: 매달 "N월 내역 올리기" 배너
```
| 단계 | 사용자의 질문 | 주 행동(accent 1개) | 통과 신호(§8) | 목표 |
|---|---|---|---|---|
| S0 발견 | 이게 뭐고, 나한테 쓸모 있나? | 무료로 시작 | `landing_cta` | — |
| S1 맛보기 | 내 데이터면 뭐가 보일까? | 내 데이터로 시작 | `demo_cta` | — |
| S2 가입 | 안전한가? 귀찮지 않나? | 카카오로 시작하기 → 동의하고 계속하기 | `consent_done` | H1 동의 85% |
| S3 파일 확보 | 파일을 어디서, 어떻게 받지? | 카드사 고르기 → 받는 법 | `guide_open` | H2 40% |
| S4 첫 올리기 | 제대로 읽혔나? | 파일 올리기 → 저장하고 분석 | `upload_done` | H1 50% · H3 90% |
| S5 Aha | 얼마를, 어디에 썼나? | (없음 — 숫자가 주인공) | 대시보드 도착 | 올린 뒤 1분 안 |
| S6 채우기 | 더 정확히 보려면? | 체크리스트의 다음 항목 | `next_step_click` | H4 · H9 |
| S7 전환 | 돈 낼 가치가 있나? | Pro 시작하기 | `checkout_start` → `checkout_pro_active` | H5 3% · H8 60% |
| S8 재방문 | 이번 달은? | N월 내역 올리기 | `upload_done` (재방문) | H6 30%/60% |

**가장 큰 이탈 지점은 S3다.** 사용자는 FinSight를 떠나 카드사 홈페이지에서 파일을 받아 와야 하고, 휴대폰에서는 그게 어렵다. 설계 노력을 S3에 가장 많이 쓴다.

## 3. Figma 7원칙 → FinSight 규칙

### 3-1. 계층 구조 — 가장 큰 글자는 제목이 아니라 답이다
- 크기는 4단계만: 핵심 숫자 `text-3xl`(화면당 1개) · 페이지 제목 `text-2xl` · 섹션 제목 `text-base font-semibold` · 본문 `text-sm`.
- 화면별 질문과 주인공:

| 화면 | 질문 | 주인공 |
|---|---|---|
| `/dashboard` | 이 달에 얼마 썼나 | N월 지출 금액 + 한 줄 요약 |
| `/upload` | 파일을 어떻게 올리나 | 파일 선택 영역 |
| `/upload/[id]` | 열이 맞나 | 미리보기 5행 + 날짜·가맹점·금액 선택 |
| `/transactions` | 무엇에 썼나 | 거래 목록 |
| `/recurring` | 매달 나가는 돈은 | 월 합계 |
| `/trends` | 늘었나 줄었나 | 추이 차트 |
| `/insights` | 무엇을 바꿀까 | 리포트 본문 |
| `/pricing` | 돈 낼 가치가 있나 | Free/Pro 차이 표 |

- 지금과 다른 점: 요약 타일 3개가 모두 `text-3xl`이라 지출이 환불·건수와 같은 무게다. 라벨 "이번 달 지출"은 지난 달을 볼 때 틀린 말이다. → B5

### 3-2. 점진적 공개 — 한 번에 한 가지 결정만
- 온보딩은 3단계로 보이고 끝이 보인다: `① 가입 → ② 파일 받기 → ③ 올리기`. 현재 단계 강조, 지난 단계 체크. → B4
- 결정 순서: 동의 → 파일 → (필요할 때만) 매핑 → 결과. 한 화면에 두 결정을 섞지 않는다.
- 첫 업로드 전에는 앱 메뉴에서 Pro 메뉴(추이·정기결제·AI 리포트·채팅)를 숨긴다. 첫 업로드 뒤 보이고, Free에게는 작은 "Pro" 표시. → B14
- Pro 기능은 데이터가 준비됐을 때 드러낸다: 정기결제는 석 달 이상(있음).
- 고급 옵션은 접는다: 매핑의 선택 열 "더 보기"(있음). 에러는 한 줄 + 가이드 링크(있음).

### 3-3. 일관성 — 같은 것은 같게
- 버튼은 4종만: Primary · Secondary · Text(UI_GUIDE) + Danger(확인 단계 전용, §3-4). `src/components/ui/button.tsx`로 모아 클래스 문자열 복붙을 없앤다. → B9
- 같은 개념은 같은 단어(§6). 지금은 "업로드/올리기", "인사이트/AI 리포트/AI 지출 리포트", "Q&A/채팅"이 섞여 있다. → B8
- 같은 상태는 같은 모양(§7). 금액 `formatKRW`, 달 `formatMonthLabel`, 기간 `formatPeriodLabel`만 쓴다.
- 새 패턴이 필요하면 이 문서나 UI_GUIDE에 먼저 적고 쓴다.

### 3-4. 대비 — 포인트 색은 다음 단계에만
- accent 채움 버튼은 화면당 1개, 그 화면의 다음 단계다. 무엇이 그 1개인지는 §5의 `primary`가 정한다.
- 보조 행동은 Secondary, 취소·나가기·자세히는 Text(muted).
- 빨강(`spend-up`)은 "지출 증가"와 파괴적 행동의 확인 버튼에만 쓴다. 에러는 `warning`(주황)이다. 에러를 빨강으로 쓰면 지출 증가와 헷갈린다.
- 파괴적 행동(업로드 삭제·전체 삭제·탈퇴): 첫 버튼은 Text, 확인 단계에서만 Danger(`border border-spend-up text-spend-up`).
- 지금과 다른 점: Free 대시보드에 accent 버튼이 최대 5개다(올릴 차례 배너, ProLock ×3, 리포트 만들기). → B1

### 3-5. 접근성 — WCAG 2.2 AA
- 대비는 글자 4.5:1(큰 글자 3:1), 입력칸 테두리·포커스 표시 같은 UI 경계 3:1. 토큰 실측값:

| 조합 | 대비 | 판정 |
|---|---|---|
| ink / body / accent 글자, surface 위 | 16.6 / 9.9 / 6.5 | 통과 |
| muted, surface / bg 위 | 5.1 / 4.7 | 통과 |
| muted·warning, accent-soft 위 | 4.4 / 4.3 | 미달 → accent-soft 위 글자는 body 이상 |
| spend-up, bg 위 | 4.49 | 근소 미달 → `#C43A2E`(bg 4.9), 7-landing에서 바꾼다 |
| line `#E1E5E2` 입력칸 테두리, surface 위 | 1.3 | 미달 → 입력·체크박스·select만 `line-strong #879089`(3.3). 토큰은 7-landing에서 추가, 앱 입력칸 적용은 B10 |
| disabled 글자 | 2.6 | 비활성 전용. 정보 글자에 쓰지 않는다 |

- 포커스: 모든 링크·버튼·입력에 `focus-visible:outline-2 outline-offset-2 outline-accent`. 지금 입력칸의 `ring-accent/30`은 흐려서 바꾼다. → B9
- 터치 대상은 44px 이상(`min-h-11`). 지금 버튼은 40px이다. → B9
- 차트 옆에는 항상 텍스트 대안(카테고리·금액·비율 목록)을 둔다. 색만으로 뜻을 전하지 않는다(증감 `+`/`−`, 있음).
- 진행·완료는 `role="status"`, 에러는 `role="alert"`, 필드 에러는 `aria-describedby`로 필드에 잇는다.
- 비활성 버튼 옆에는 이유를 적는다(동의 화면 방식, 있음).
- 본문은 최소 `text-sm`(14px). `text-xs`는 "마지막 확인 날짜" 같은 부가 정보만.

### 3-6. 근접성 — 가까우면 한 덩어리
- 간격이 관계를 말한다: 덩어리 안(라벨·값·보조 설명) `gap-1`~`gap-2` < 요소 사이 `gap-3`~`gap-4` < 섹션 사이 `space-y-8`.
- 행동은 대상 바로 옆: "다시 분류"는 "분류 실패 N건" 옆, 카테고리 변경은 그 거래 행에서, Pro 잠금 문구는 잠긴 내용 바로 아래.
- 필드 에러는 필드 바로 아래, 페이지 에러는 제목 아래.
- 파괴적 행동은 떼어 놓는다: 설정 맨 아래 "데이터 삭제·탈퇴" 구역을 `border-t`와 `space-y-8`로 분리하고, 구독 관리 버튼과 한 줄에 두지 않는다.
- 금액과 증감은 붙인다: `₩1,234,000 · +12%`.

### 3-7. 정렬 — 기준선 하나
- 모든 화면이 같은 좌측 기준선을 쓴다: `max-w-5xl px-4`, 카드 안쪽 `p-5`. 중앙 정렬 금지(UI_GUIDE). 예외는 버튼 안 글자뿐이다.
- 숫자 열은 오른쪽 정렬 + `tabular-nums`(TOP5·거래·정기결제·요금표). 자릿수가 세로로 맞아야 비교가 된다.
- 라벨과 값을 가로로 놓을 때는 `items-baseline`. 그리드는 모바일 1열, `md`부터 2~3열.

### 3-8. 실천 팁 4가지를 FinSight에 적용하기
- **사용자 관점:** 메뉴와 화면을 사용자 순서(받기 → 올리기 → 보기 → 채우기 → 더 알기)대로 놓는다. 메뉴: 대시보드 · 거래 · 올리기 | 추이 · 정기결제 · AI 리포트 · 채팅 | 설정.
- **간편하게:** 이미 있는 지름길(같은 형식 자동 확정, 마지막 카드 기본 선택, 결과에서 그 달 대시보드로, 로그인 뒤 원래 가던 곳)은 **문구로 알려야** 효과가 난다. 예: "다음부터는 확인 없이 바로 올라가요."
- **단축 기능:** 대시보드·AI 리포트에서 ←/→ 키로 달 이동. → B15
- **테스트:** §9.

## 4. 단계별 설계

### S0 발견 — `/` (확정 시안 `docs/design/landing-v1.html`, 구현 phase `7-landing`)
- 5초 안에 "무엇을, 무엇으로, 얼마에"를 답한다. 말하지 말고 **AI의 결과물을 보여 준다.** 시각 규칙은 UI_GUIDE "랜딩 예외".
- 순서와 역할:

| # | 섹션 | 보여 주는 것 | `section` 값 |
|---|---|---|---|
| 1 | 히어로 | 약속형 제목 "월급이 어디로 새는지, 파일 하나로 AI가 찾아 드려요" + 변환 시퀀스(엑셀 행 → AI가 카테고리 열을 채움 → 카테고리 막대 → 어두운 AI 리포트 카드) | `hero` |
| 2 | 새는 돈이 숫자로 보여요 | 큰 숫자 4개 + 미니 그래프: 정기결제 월 합계, 전월 대비 늘어난 카테고리, 주말 비율, 1위 카테고리 | `tiles` |
| 3 | AI 리포트 | 리포트 카드 + ①숫자는 서버 ②문장은 AI(숫자 없이) ③실천 팁 설명, 채팅(Pro) 예시 | `report` |
| 4 | 시작하는 법 | 3단계 흐름(카드사 → 최근 3개월 엑셀 → 올리기), 카드사 이름, 휴대폰 안내 | `steps` |
| 5 | 데이터 흐름 | 파일 → FinSight 서버 → AI에 보내는 것(기능별), 보내지 않는 것, 90일 삭제 타임라인 | `trust` |
| 6 | 요금 | Free(첫 AI 리포트 1회 무료 강조) · Pro | `pricing` |
| 7 | FAQ | | `faq` |
| 8 | 마지막 CTA | 전체 폭 `bg-accent` 띠 | `final` |

- 버튼: [무료로 시작](Primary) [로그인 없이 예시 보기](Secondary). 마지막 CTA에서 한 번 더.
- 숫자는 모두 `getLandingShowcase()`가 데모 데이터에서 계산해 `/demo`와 맞춘다. 코드가 계산한 통계를 "AI가 찾았다"고 쓰지 않는다.
- 헤드라인 테스트 후보(2주 주기, 한 번에 하나만 바꾼다): 질문형 "지난달 배달에 얼마 썼는지 아세요?", 손실형 "잊고 있던 구독료, 매달 새고 있을지 몰라요". A/B는 주 방문자 1,000명을 넘은 뒤.

### S1 맛보기 — `/demo`
- 상단 배너 "샘플 데이터예요 · 실제 화면과 같아요 [내 데이터로 시작]"(있음)과 같은 CTA를 페이지 끝에 한 번 더 둔다. → B7(데모 부분)
- Pro 영역에는 "Pro" 라벨을 붙여 무료 범위를 오해하지 않게 한다. 월 이동은 막지 않는다(있음).

### S2 가입 — `/login` → `/onboarding/consent`
- 두 화면 모두 위에 진행 표시(①이 현재 단계). → B4
- 카카오 Primary, 구글 Secondary, 인앱 브라우저 안내(있음). 로그인 뒤 원래 가던 곳으로(`next`, 있음).
- 동의: 4개 개별 체크 + 모두 동의 + 비활성 이유(있음). 버튼 문구 "시작하기" → "동의하고 계속하기". → B8
- 가입 단계에서는 Pro·요금 이야기를 하지 않는다.

### S3 파일 확보 — `/upload` 첫 방문, `/guide`
| 이탈 원인 | 대응 |
|---|---|
| 카드사 메뉴를 못 찾는다 | 업로드 화면 안에서 카드사를 고르면 받는 법이 바로 펼쳐진다. `/guide`로 떠나지 않게 한다(`IssuerGuideList` 재사용). |
| 휴대폰이라 엑셀 저장이 안 된다 | 좁은 화면(`md:hidden`)에서는 받는 법보다 먼저 "PC에서 열 링크 복사"(`CopyLinkButton`)와 "카톡 나와의 채팅에 붙여 두세요"를 보여 준다. |
| 청구서·은행 파일을 받는다 | 받는 법 첫 줄: "'청구서'가 아니라 **'이용내역'**을 받아요." 잘못 올리면 원인별 안내(있음). |
| 한 달 치만 받아서 결과가 빈약하다 | 받는 법 3단계를 "기간은 **최근 3개월**로 골라요"로 바꾼다. 첫 업로드부터 전월 비교·정기결제 티저가 살아난다. |
| 암호 걸린 엑셀 | 받는 법 끝에 "암호를 걸었다면 풀고 저장해요" 한 줄. |

- 화면 구성(첫 방문): 제목 "내역 올리기" + 진행 표시(① 완료) 아래 번호 붙은 두 구역, "② 파일 받기"(카드사 선택 → 4단계)와 "③ 올리기"(카드 이름 + 파일). 두 번째 방문부터 ②는 "파일은 어디서 받나요?" 링크 한 줄로 접는다. → B3·B4

### S4 첫 올리기 — `/upload`, `/upload/[id]`
- 파일 선택 영역은 넓게 만든다. 끌어다 놓기와 클릭을 둘 다 받고, 영역 안에 "CSV·xls·xlsx · 10MB 이하"를 적는다. → B12
- 카드 이름이 비었다는 경고는 파일을 고른 뒤에만 보인다. 처음부터 주황 경고를 띄우지 않는다. 입력칸 예시는 "예: 신한카드". → B12
- 처리 중에는 파일마다 단계를 보여 준다: `파일 확인 · 열 분석 · 거래 분석 · 완료`. 지금 단계를 강조하고 끝난 단계는 체크한다. 문구 "끝날 때까지 이 화면을 닫지 마세요"를 붙인다. 브라우저가 단계를 이어서 호출하기 때문이다. → B12
- 매핑 확인은 "처음 보는 형식이라 한 번만 확인해 주세요. 다음부터는 바로 올라가요."로 시작한다. 필수 3열만 먼저 보이고, 선택한 열은 미리보기에서 강조된다(있음).
- 결과는 "7~9월 · 132건 추가 · 이미 있던 12건" 다음에 [대시보드 보기](Primary, 결과의 마지막 달로)와 [다른 카드 내역 올리기](Secondary)를 둔다. 파일이 여러 개면 Primary는 마지막 결과 아래 하나만 둔다. → B12

### S5 Aha — `/dashboard` 첫 도착
- 위에서 아래로: (올릴 차례 배너) → 제목·월 선택 → **한 줄 요약** → 지출 타일(주인공)과 환불·건수(보조) → 카테고리 → TOP5 → 거래 전체 보기 → 시작 체크리스트(§5) → Pro 영역.
- 한 줄 요약은 서버 집계로 만든다. AI를 쓰지 않으니 바로 뜬다. 예: "9월에 ₩1,234,000 썼어요. 식비가 32%로 가장 많아요." 환불이 더 많은 달은 "9월에는 환불이 더 많았어요." → B5
- 분류를 고칠 수 있다는 걸 알린다. TOP5 아래에 "카테고리가 틀리면 거래를 눌러 바꿀 수 있어요"를 둔다.
- 체크리스트는 숫자 **아래**에 둔다. 첫 도착의 주인공은 숫자다.

### S6 채우기
- 데이터가 많을수록 가치가 커진다. 석 달이 쌓이면 정기결제와 추이를 보고, 카드가 여러 장이면 전체 지출이 보인다. 이 제안을 시작 체크리스트로 한 번에 하나씩 한다.
- 카테고리 수정은 "같은 가맹점 모두"로 한 번에 끝난다(있음).
- 첫 AI 리포트(무료)가 체크리스트 마지막 항목이다. 석 달이 먼저인 이유: 비교할 달이 있어야 리포트가 좋아지고, 그만큼 H9가 오른다.

### S7 전환
- Pro 권유는 Aha 뒤에만 한다. 랜딩 요금 섹션과 `/pricing`을 빼면, 첫 대시보드 전에는 Pro를 권하지 않는다.
- 티저에는 **사용자 자신의 숫자**를 쓴다. 정기결제는 "5건 · 월 ₩47,600"(있음). 전월 비교는 방향만 공개한다: "8월보다 지출이 늘었어요. 어디서 늘었는지는 Pro에서 볼 수 있어요." 금액과 카테고리는 잠근다. 추이는 흐리게(있음). → B11
- Pro 영역의 전환 버튼은 하나다. 나머지 잠금은 Text 링크 "Pro에서 보기"로 둔다. → B1
- 잠금에서 `/pricing?from=recurring`으로 가고, 결제 뒤에는 그 화면으로 돌아온다(`returnTo`). → B11
- `/pricing` 순서: 무엇이 열리나(표) → 가격 → 해외결제 카드 조건(버튼 위, 있음) → 버튼.
- 결제 성공 화면: "Pro가 열렸어요" + 열린 기능 목록 + [보던 화면으로]. → B11

### S8 재방문
- 이메일 리마인더는 없다(MVP). 대시보드 첫 줄 배너가 유일한 장치다: "10월 내역을 올릴 차례예요. 같은 카드사 형식이면 확인 없이 바로 올라가요 [10월 내역 올리기]". → B8
- Pro는 새 달 데이터가 들어오면 "10월 AI 리포트 만들기"가 다음 단계가 된다(§5).
- H6가 낮으면 다음 버전에서 리마인더를 넣는다(PRD). 그 전의 싼 대안은 캘린더(.ics) 추가다. → B16

## 5. 다음 단계 장치 — 시작 체크리스트
"다음에 뭘 하지?"를 사용자가 고민하지 않게 한다. **새 테이블 없이** 이미 있는 값에서 계산한다. → B2

```ts
// src/lib/domain/journey.ts — 순수 함수, 같은 폴더에 journey.test.ts
export interface JourneyInput {
  isPro: boolean;
  monthsWithData: number;         // 거래가 있는 달 수 (availableMonths.length)
  freeInsightAvailable: boolean;  // Free 첫 리포트 무료가 남았나
  staleMonth: YearMonth | null;   // 올릴 차례인 달 (지금의 uploadBannerMonth)
  hasInsightThisMonth: boolean;
}
export type StepKey = "signup" | "first_upload" | "three_months" | "first_insight";
export interface Journey {
  checklist: { key: StepKey; done: boolean; progress?: { now: number; goal: number } }[] | null; // Free이고 미완료일 때만
  primary: "stale_upload" | StepKey | "pro_insight" | "pro_upgrade" | null; // accent 버튼을 가질 단 하나
}
```

| 체크리스트 (Free) | 완료 조건 | 행동 |
|---|---|---|
| ① 가입하기 | 항상 완료 | — |
| ② 첫 카드 내역 올리기 | `monthsWithData ≥ 1` | — |
| ③ 석 달 치 채우기 · N/3달 — "정기결제와 전월 비교를 찾아 드려요" | `monthsWithData ≥ 3` | [지난 내역 올리기] → `/upload` |
| ④ 첫 AI 리포트 받기 · 무료 | `!freeInsightAvailable` | [리포트 만들기] → `/insights?month=` |

- 제목은 "시작하기 · 4단계 중 2단계 완료". ①②가 처음부터 완료로 보이므로 이미 절반쯤 왔다고 느껴진다. 다 끝나면 체크리스트가 사라진다. 닫기 버튼은 두지 않는다(MVP).
- 완료되지 않은 항목도 모두 누를 수 있다. accent는 `primary` 하나에만 주고, 나머지 항목은 Text 링크다.

`primary` 우선순위(위가 먼저):
1. `staleMonth`가 있음 → `stale_upload` (Free·Pro 공통, 화면 맨 위 배너)
2. Free이고 체크리스트가 미완료 → 첫 미완료 항목
3. Pro이고 이번 달 리포트가 없음 → `pro_insight`
4. Free이고 체크리스트가 완료 → `pro_upgrade` (Pro 영역의 버튼 하나)
5. 그 외 → `null`

## 6. 문구 사전
| 쓴다 | 쓰지 않는다 | 메모 |
|---|---|---|
| 이용내역 | 명세서, 거래내역 | 카드사 메뉴 이름과 같게. "청구서"는 거부 안내에서만. PDF 파일을 가리킬 때만 "PDF 명세서"(ADR-012) |
| 내역 올리기 · 파일 올리기 · 올렸어요 | 업로드(화면 문구) | 코드·경로의 `upload`는 그대로 |
| 가맹점 | 사용처, 상점 | |
| 카테고리 | 분류(명사) | "분류"는 동작에만: 자동 분류, 다시 분류 |
| N월 지출 | 이번 달 지출, 총지출 | 보고 있는 달을 말한다 |
| 정기결제 | 구독, 반복결제 | |
| AI 리포트 | 인사이트, 인사이트 리포트, AI 지출 리포트 | 메뉴 이름도 "AI 리포트" |
| 채팅 | Q&A, 지출 Q&A | 설명은 "내 지출에 대해 물어보기" |
| 추이 · 전월 비교 | 트렌드, 월간 비교 | |
| Pro 시작하기 | 업그레이드, 구독하기 | |
| 해지 | 구독 취소 | "취소"는 거래 취소에만 |

- 버튼은 결과나 목적지를 말한다: "대시보드 보기", "10월 내역 올리기", "동의하고 계속하기". "확인"·"다음"·"여기를 클릭"은 쓰지 않는다.
- 다음 단계 제안은 "얻는 것 + 행동"으로 쓴다: "석 달 치를 채우면 정기결제를 찾아 드려요 [지난 내역 올리기]".
- 시간·효과 약속은 측정한 것만 쓴다. "1분이면 돼요"는 측정 전에는 쓰지 않는다.
- 신뢰 문구는 데이터를 다루는 지점에 한 줄로 둔다. 업로드 옆에 "원본은 90일 뒤 자동 삭제", AI 기능 옆에는 그 기능이 보내는 것만 적는다(리포트 "합계·비율만 보내요", 분류 "가맹점명만 보내요"). 채팅은 거래 30건 이하를 보내므로 "집계값만"이라고 쓰지 않는다.
