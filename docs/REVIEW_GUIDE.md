# 리뷰 가이드

코드 리뷰의 심각도·판정·출력 형식. `/review-code`의 차원 에이전트(`.claude/agents/review-*.md`)와 사람이 같은 기준을 쓴다. 차원마다 무엇을 볼지는 각 에이전트 파일에 있다.

## 심각도

| 심각도 | 기준 | FinSight 예 |
|---|---|---|
| 🔴 critical | 배포하면 바로 사고가 난다. 다른 사용자 데이터, 돈, 비밀키, 동의 없는 데이터 전송에 닿는다 | RLS 없는 새 테이블 · `handler()`를 거치지 않는 쓰기 · 비밀 env가 클라이언트 번들에 들어감 · 거래·가맹점·금액이 로그나 Claude로 규칙보다 많이 나감 · `requireConsent()` 없이 Claude 호출 · 웹훅 서명 검증 없음 · `requirePro()` 없는 Pro 기능 |
| 🟠 major | 규칙 위반이나 버그지만 특정 조건에서만 터진다. 머지 전에 고친다 | 저장이 실패하면 `ai_usage`가 기록되지 않음(일일 상한 우회) · 바뀐 동작에 테스트 없음 · 호출 순서만 고정해서 버그를 숨기는 테스트 · 사용자가 바꿀 수 있는 컬럼을 서버가 그대로 믿음 |
| 🟡 minor | 지금 동작은 맞지만 약한 곳이다. 다음 작업에서 고쳐도 된다 | 실패 경로 테스트 일부 누락 · 경계값 테스트 부족 · 마스킹이 승인번호처럼 민감도 낮은 값을 남김 |
| ⚪ nit | 취향·이름·주석. 안 고쳐도 된다. 차원당 3개까지만 적는다 | 테스트 이름 · 중복된 mock 설정 |

- 헷갈리면 "배포하면 누가 어떤 피해를 보나"로 정한다. 피해가 생기는 실패 시나리오를 한 문장으로 적을 수 없으면 한 단계 낮춘다.
- 근거(`file:line`)가 없는 추측은 적지 않는다.

## 판정

개수로 정한다. 판단을 더하지 않는다.

| 판정 | 조건 |
|---|---|
| Blocked | 🔴 1개 이상, 또는 `scripts/verify.sh` FAIL |
| Changes Requested | 🟠 1개 이상 |
| Approve | 그 외(🟡·⚪만 있거나 지적 없음). 모든 차원이 보고를 마쳤을 때만 낸다 |

## 인라인 코멘트

위치 한 줄 다음에 4줄. 한 줄에 한 문장.

```
src/services/claude/classifier.ts:NN
[🔴 critical] 분류 요청에 금액·날짜가 함께 나감
TL;DR 가맹점을 분류하려고 거래 행 전체를 넘겨서 금액·날짜까지 Claude로 간다.
✓ Good 분류 요청에는 가맹점명(merchant_key)만 담긴다.
→ Fix `await claude.classify(rows.map((r) => r.merchant_key))`
```

- `[심각도] 제목`: `🔴 critical` · `🟠 major` · `🟡 minor` · `⚪ nit`. 제목은 무엇이 문제인지 한 구절.
- `TL;DR`: 언제 무엇이 어떻게 깨지는지(실패 시나리오).
- `✓ Good`: 올바른 상태(기대 동작). 규칙이나 불변식으로 적는다.
- `→ Fix`: 그 상태로 가는 코드. 한 줄로 안 되면 바꿀 함수와 순서를 적는다.
- 같은 파일에서 원인이 같은 지적은 줄이 달라도 하나로 합친다. 위치는 원인이 있는 줄, 심각도는 높은 쪽을 따르고 차원은 모두 적는다.

## 전체 요약

리뷰 하나에 하나, 인라인 코멘트보다 먼저 쓴다.

```
## 판정: Blocked
범위 `abc1234..def5678` (마지막 리뷰 기록 이후) · 차원 security·privacy·tests · verify PASS lint/test/build
🔴 1 · 🟠 1 · 🟡 2 · ⚪ 0

**Walkthrough**
(2~3줄. 이 범위가 무엇을 바꿨는지)

**잘된 점**
- (2~3개)

**Critical / Major**
1. 🔴 `src/services/claude/classifier.ts:NN` 분류 요청에 금액·날짜가 함께 나감 (privacy)
2. 🟠 `src/services/claude/classifier.test.ts:NN` Claude로 가는 요청 내용을 검사하지 않음 (tests)

**다음 액션**
1. (고칠 순서와 확인할 테스트)
2. 고친 뒤 `/review-code` 다시 실행
```

- 🟡·⚪는 요약에 개수만 적고, 내용은 인라인 코멘트에만 쓴다.
- Critical / Major가 없으면 "없음"이라고 적는다.

## 차원 에이전트 보고

차원 에이전트는 메인에 이 형식으로 돌려준다.

```
## <차원>
확인한 항목: 1 ✓ · 2 ✓ · 3 해당 없음 · …
잘된 점:
- `file:line` 한 줄 (1~2개)

<인라인 코멘트, 심각도순. 없으면 "지적 없음">
```
