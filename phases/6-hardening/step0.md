## 배경

리뷰에서 `maskDigits`가 계좌번호를 마스킹하지 못하는 것이 재현됐다. 마스킹된 값은 매핑 샘플로 Claude에 가고, 가맹점명(`merchant_raw`·`merchant_key`)으로 저장되며 분류 요청에도 들어간다.

| 입력 | 지금 결과 | 원인 |
|---|---|---|
| `3333-01-1234567` (카카오뱅크 계좌) | 그대로 | 날짜 보호 정규식 `\d{4}-\d{1,2}-\d{1,2}`가 `3333-01-12`를 날짜로 보고 떼어 낸다(앞뒤 경계 없음) |
| `123456-01-123456`, `1234-56-789012` | 그대로 | 같은 원인 |
| `30012345` (8자리 승인번호 등) | 그대로 | 8자리 숫자는 전부 날짜로 보고 보호한다 |
| `송금 ０１０-１２３４-５６７８` (전각 숫자) | 전각 그대로 → 이후 NFKC로 `010-1234-5678`이 되어 저장·전송 | `\d`가 전각 숫자와 맞지 않는데, NFKC는 마스킹 **뒤**에 적용된다 |

## 작업

TDD로 진행한다. 먼저 `mask.test.ts`에 아래 표를 테스트로 추가해 실패를 확인한 뒤 고친다.

### `src/lib/ingest/mask.ts`의 `maskDigits(text: string): string` (시그니처 유지)

1. **맨 처음에 `text.normalize("NFKC")`를 적용한다.** 그러면 전각 숫자·기호가 ASCII가 된 뒤 마스킹된다. `maskSamples`와 `parseRows`는 모두 `maskDigits`를 거치므로 이 한 곳만 고친다.
2. **날짜로 보호하는 범위를 실제 날짜로 좁힌다.** 날짜 보호는 "시간이 붙은 날짜가 7자리 이상이라 `#`가 되는 것"을 막으려는 장치다.
   - 구분자 날짜는 연도 `19xx`/`20xx`, 월 1–12, 일 1–31일 때만 보호한다. 구분자는 `.`·`-`·`/`이고 뒤에 시각(`HH:MM[:SS]`)이 붙을 수 있다.
   - 8자리 날짜 `YYYYMMDD`는 같은 연·월·일 조건을 만족할 때만 보호한다.
   - 앞뒤 경계가 있어야 한다. 앞 글자가 숫자이거나 `-`·`.`·`*`이면 날짜가 아니다. 날짜 뒤에 바로 숫자가 오거나, `-`·`.`·`*`와 숫자가 이어지면 날짜가 아니다. 이런 경우 더 긴 숫자 토큰의 일부로 보고 마스킹 대상에 넣는다.
3. 나머지 규칙은 그대로다. 구분자(`-`·공백·`*`·`.`)가 섞여도 숫자가 7개 이상인 연속 토큰은 `#`로 바꾼다. **쉼표는 구분자가 아니다.** 그래서 `1,234,567` 같은 금액은 유지된다.

### 테스트로 고정할 표 (`maskDigits`)

| 입력 | 기대 |
|---|---|
| `3333-01-1234567` | `#` |
| `123456-01-123456` | `#` |
| `1234-56-789012` | `#` |
| `30012345` | `#` |
| `０１０-１２３４-５６７８` | `#` |
| `송금 ０１０-１２３４-５６７８` | `송금 #` |
| `2024-01-15 1234567` | `2024-01-15 #` |
| `2024-01-15` | 그대로 |
| `2024.01.15 13:45` | 그대로 |
| `2026.09.01 12:34` | 그대로 (기존 테스트) |
| `20240115` | 그대로 |
| `1,234,567` · `12.99` | 그대로 (기존 테스트) |

- 기존 `mask.test.ts`의 마스킹·보존 케이스는 모두 계속 통과해야 한다.
- `maskSamples` 테스트에 행 하나를 추가한다: 계좌번호 `3333-01-1234567`이 든 셀이 샘플 결과에 원문 숫자를 남기지 않는지 확인한다.
- `parse.test.ts`에 한 케이스를 추가한다: 가맹점 셀 `카카오페이 송금 ０１０-１２３４-５６７８`을 파싱하면 `merchantRaw`와 `merchantKey` 어디에도 `010`·`1234`·`5678`이 남지 않는다.

## 금지사항

- 금액 형식(`1,234,567`, `12,000원`, `-5,000`)을 마스킹하지 마라. 이유: `maskSamples`의 금액 열 샘플이 망가지면 Claude가 금액 열을 매핑하지 못한다.
- 마스킹 규칙을 약하게 만들어 기존 마스킹 테스트를 바꾸지 마라. 이유: 이 step의 목적은 누출을 막는 것이다.
- `maskSamples`의 텍스트 셀 규칙(`첫 글자***(N자)`)과 헤더 처리는 바꾸지 마라. 이유: 이번 결함과 무관하다.
- 기존 테스트를 깨뜨리지 마라.
